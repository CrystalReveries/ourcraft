# 多人（LAN < 10 人）技术方案

目标：局域网内 1~10 名玩家共享同一个 64×48×64 世界，低延迟、可持久化、防简单作弊。
技术选型：**Node.js 权威服务器 + WebSocket**（无需公网服务，房主本机启动）。

## 1. 架构
```
浏览器客户端 ×N  ──WebSocket(JSON/binary)──►  Node 权威服务器 (20Hz)
   │  本地预测/插值                              │  世界状态（唯一真相）
   │  渲染（Babylon）                            ├─ 校验：距离/高度/频率
   └─ 输入上行                                   ├─ 广播差分
                                                └─ 持久化 world.json
```

- **服务器权威**：所有方块变更、生物位置/伤害、时间/天气由服务器裁决
- **客户端**：本地预测自身移动（不等待服务器），对其他玩家/生物做插值
- **理由**：<10 人局域网流量极小（关键帧 ~几 KB/s），权威服务器实现简单且防作弊

## 2. 前置重构（必须）
当前 `world.ts` 混合了体素数据与 Babylon 渲染，服务器无法复用。拆分：
```
src/shared/config.ts      // 方块定义、常量（两端共用）
src/shared/voxel.ts       // Uint8Array 世界、get/set、生成、红石、放置校验（纯逻辑）
src/shared/protocol.ts    // 消息类型 + 编码/解码 + 校验
src/client/render.ts      // 图集/主网格/实例/材质（仅客户端）
src/client/main.ts        // 引擎/输入/UI
server/index.ts           // ws 服务器、房间、tick、持久化
```
> 拆分后单人模式 = 本地内嵌服务器（可直接用同一套代码，mode=single）。

## 3. 协议（v1）
传输：WebSocket 文本帧 JSON（可读、易调试；<10 人足够）。
世界坐标：整数方块坐标 + 玩家 float32 位置。

### 客户端 → 服务器
| 消息 | 字段 | 说明 |
|---|---|---|
| `hello` | `{name, version}` | 加入请求；版本不符则拒绝 |
| `input` | `{seq, pos, yaw, pitch, onGround}` | 20Hz 上行自身状态 |
| `block` | `{x,y,z,action:"place"\|"break", blockId?}` | 方块操作请求 |
| `chat` | `{text}` | 聊天（限长 200） |
| `cmd` | `{text}` | 管理员命令（仅房主） |
| `ping` | `{t}` | 延迟测量 |

### 服务器 → 客户端
| 消息 | 字段 | 说明 |
|---|---|---|
| `welcome` | `{id, tick, world: RLE(base64), players, time, weather}` | 加入快照（RLE 压缩体素） |
| `join` / `leave` | `{id, name, pos}` | 玩家进出 |
| `state` | `{tick, players:[{id,pos,yaw,pitch,hp}], mobs:[{id,type,pos,yaw,hp}]}` | 20Hz 全量状态（<10 人可接受） |
| `blocks` | `{changes:[[x,y,z,id],...]}` | 方块差量（tick 内合并） |
| `reject` | `{reason}` | 拒绝放置/破坏（回滚客户端预测） |
| `chat` | `{from, text}` | 广播聊天 |
| `env` | `{time, weather}` | 时间/天气（10s 或变化时） |
| `kick` | `{reason}` | 封禁/踢出 |

### 校验规则（服务器）
- 目标坐标必须在世界内且 `y ≤ BUILD_LIMIT`
- 挖/放距离 ≤ `REACH + 0.5`（按玩家上报位置，允许少量误差）
- 基岩不可破坏；放置目标必须为空气；红石元件需下方为实体
- 频率限制：方块操作 ≤ 8 次/秒（超限丢弃并记录）
- 移动校验：单 tick 位移 ≤ 速度上限 × dt × 1.5（超出则拉回，不直接踢）
- `hello` 后 5s 内无 `input` 则超时断开

## 4. 同步细节
| 项目 | 策略 |
|---|---|
| 服务器 tick | 20Hz 固定步长（50ms），累积器驱动 |
| 自身移动 | 客户端预测 + 服务器 `state` 校正（误差 >0.5 格时平滑拉回，否则忽略） |
| 其他玩家 | 保存最近 2 个快照，按 100ms 延迟插值渲染 |
| 生物 | 服务器 AI 权威，客户端只做位置/朝向插值 |
| 方块 | 客户端立即应用 + 服务器确认；被拒则回滚并提示 |
| 时间/天气 | 服务器计算（`Environment` 逻辑移至 shared），随 `env` 广播 |
| 时钟 | `ping/pong` 估算 RTT，仅用于显示 |

## 5. 生物与红石
- 生物 AI（A*、攻击、物理）跑在服务器（`mobs` 逻辑改为 shared 纯逻辑 + 无渲染）
- 红石在服务器重算，把 `dustOn/lampLit` 的变化作为方块 id 变体广播
  （客户端只切换实例的 master，不重算逻辑）
- 玩家受伤/死亡由服务器判定并下发 `hp`

## 6. 房间与管理
- 房主执行 `npm run server`，控制台打印 `ws://192.168.x.x:8787` 与二维码
- 最多 10 人（超出 `reject: room_full`）
- 房主（第一个连接，或 `--admin-token`）拥有管理面板权限：踢人/封禁/时间/天气/刷怪
- 封禁：`bans.json` 记录 `name` + `ip`，支持 `/ban <name>`、`/unban <name>`
- 聊天：`T` 区分命令（`/` 开头）与聊天；系统消息单独颜色

## 7. 持久化
- 每 60s 或最后一名玩家离开时保存
- `world.json`：`{version, size:[64,48,64], blocks: RLE(base64)}`（RLE 后 <100KB）
- `players.json`：名字、位置、金币、工具（可选）
- 启动参数 `--world <path>`；损坏时回退到新生成

## 8. 测试计划
1. **单元**：协议编解码、RLE 往返、校验规则（超距/越界/频率）
2. **集成**：Node 启动 2 个 ws 客户端 → 编辑方块 → 双方收到一致 diff
3. **手测**：2 个浏览器标签 + 1 台手机同 LAN 游玩；观察位置平滑与方块一致
4. **故障**：断网 5s 重连、服务器重启后世界恢复、超频请求被丢弃

## 9. 里程碑
| 阶段 | 交付 |
|---|---|
| M1 | shared 拆分 + 单人模式改为本地服务器（功能不回归） |
| M2 | 服务器房间 + 加入快照 + 玩家位置同步（能互相看到） |
| M3 | 方块同步 + 校验 + 红石/时间/天气权威 |
| M4 | 生物服务器 AI + 伤害/死亡同步 |
| M5 | 管理/封禁/聊天/持久化 + 10 人压测 |
