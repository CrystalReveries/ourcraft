# 路线图

## Phase 1 — 单人可玩（已完成 ✅）
世界生成（地形/矿脉/树/村庄）、挖掘建造、12+ 方块、红石四件套、三种生物 + A* 寻路、
昼夜与天气、经济与工具档位、管理面板/命令/封禁、性能优化、几何 UT、视觉回归流程。

---

## Phase 2 — 生物细节与贴图（下一步）
**目标**：让生物从"色块盒子"变成有部件、有贴图、有动作的实体。

### 2.1 多部件模型
- 每个类型拆为 `head / body / legs×2(或×4) / arms(僵尸)`，挂在 `TransformNode` 下
- 保留现有 AABB 碰撞箱尺寸不变（视觉与碰撞分离，命中仍精确）
- 记录各部件相对脚底原点的偏移，便于行走动画

### 2.2 贴图
- 每个生物类型一张 64×64 `DynamicTexture`（程序化绘制：皮肤、眼睛、衣服）
- 材质 `StandardMaterial` + `diffuseTexture`，不使用图集（避免与方块图集的 alpha 规则混淆）
- 可选：生物脚底阴影（半透明圆片贴地）

### 2.3 动画
- 行走：腿部绕髋部 `rotation.x` 正弦摆动，幅度 ∝ 速度；空闲时轻微呼吸缩放
- 僵尸：手臂前伸（固定 rotation.x），头部朝向玩家（yaw 跟随）
- 受击：短促缩放/位移抖动（现有击退已有位移反馈）

### 2.4 表现力
- 名字/血条：`DynamicTexture` 平面广告牌（受伤时短暂显示血条）
- 死亡：缩小 + 淡出后销毁（0.3s）
- 音效（可选，Phase 4）

### 验收
- 三种生物外观可区分、行走有腿部动作、攻击有反馈、F3 碰撞箱仍精确
- 截图回归：`?debug&up` 白天/夜晚各一张

## Phase 3 — 局域网多人（<10 人，核心目标）
详细方案见 [multiplayer.md](./multiplayer.md)。前置重构：

1. **拆分世界逻辑与渲染**（必须）
   - `src/world/data.ts`：体素读写、地形/村庄生成、红石规则、放置/破坏校验（纯逻辑，无 Babylon）
   - `src/world/render.ts`：图集、主网格、实例、材质
   - `src/protocol.ts`：客户端/服务器共享的消息类型与校验函数
2. **服务器**：`server/` 下 Node + `ws`（或 `uWebSockets.js`），20Hz tick，权威世界
3. **客户端**：预测移动 + 位置插值（100ms 缓冲），服务器校正
4. **房间**：LAN 直连 `ws://<host-ip>:8787`，最多 10 人；可选 mDNS 发现
5. **管理**：房主即管理员（P 面板/命令），封禁按用户名 + IP，聊天与系统消息
6. **持久化**：退出时 `world.json`（RLE 压缩）+ `players.json`

### 验收
- 2~10 个客户端同时在线，方块编辑一致、玩家位置平滑、重连可用
- 服务器 CPU < 20%（10 人，64×48×64）
- 断线重连后世界一致；作弊包（超距放置）被拒绝

## Phase 4 — 长期扩展
- 存档/读档与多世界；生物群系（沙漠/雪原/森林）与洞穴
- 更多方块与合成系统（工作台/熔炉）；水与流体
- 声音（脚步/挖掘/生物/天气）、音乐
- 移动端触屏控制（虚拟摇杆 + 点击挖掘）
- 光影：方向光阴影（CSM）、环境光遮蔽（AO）
