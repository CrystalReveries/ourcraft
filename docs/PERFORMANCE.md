# PERFORMANCE.md — 性能优化计划

## 现象
游戏卡顿（低 FPS）。定位到以下瓶颈，按影响从大到小排序。

## 瓶颈分析
| # | 瓶颈 | 位置 | 影响 |
|---|---|---|---|
| 1 | 每次挖/放方块全图扫描红石元件（64×48×64 ≈ 19.7 万格） | `world.ts recomputeRedstone()` | 每次破坏方块卡 5~20ms，按住左键连续挖掘时持续卡顿 |
| 2 | ~7000 个静态方块实例每帧重算世界矩阵 | `world.ts spawnInstance()` | 每帧数千次矩阵乘法，纯浪费（方块不动） |
| 3 | 鼠标移动触发场景拾取 | Babylon 默认行为 | 每次鼠标移动做一次射线检测，视角转动时持续消耗 |
| 4 | 每帧分配临时 Vector3/Color3/Color4 | `main.ts` `systems.ts` | GC 压力导致周期性掉帧 |
| 5 | 雨粒子系统容量过大 | `systems.ts` | 下雨时 GPU/CPU 压力 |
| 6 | 高 DPI 屏幕填充率过高 | 引擎默认 | 4K/HiDPI 下 GPU 瓶颈 |

## 优化方案
### P0（立竿见影）
1. **红石增量维护**：新增 `redstoneCells` 注册表（Map，仅存红石元件格子），
   放置/破坏时增量更新；仅当变更位置 3×3×3 邻域内存在元件才触发重算，
   重算本身只遍历注册表（通常 <100 项）而非全图。
2. **冻结世界矩阵**：所有方块实例与主网格调用 `freezeWorldMatrix()`
   （静态几何，一次计算永久缓存）。红石换色/挖掘重建时走 `spawnInstance`
   统一路径，创建后立即冻结。
3. **关闭指针移动拾取**：`scene.skipPointerMovePicking = true`（本游戏用自研
   DDA 射线，不需要 Babylon 拾取）。

### P1（降低 GC）
4. 主循环移动向量、环境系统天空色/太阳方向全部改为模块级临时对象 +
   `set()/copyFrom()/LerpToRef()`，零分配。
5. 挖掘射线直接传 `camera.globalPosition`（只读，去掉 `.clone()`）。

### P2（自适应兜底）
6. 雨粒子容量 2200→1400。
7. **自适应分辨率**：持续 FPS<24 时按 25% 步进降低渲染分辨率
   （`engine.setHardwareScalingLevel`，单向降档），并在聊天栏提示。
8. `scene.blockMaterialDirtyMechanism = true`（材质全部静态，禁止脏检查传播）。

## 预期效果
- 挖掘/放置从"每次卡顿"变为无感（19.7 万格扫描 → <100 项遍历）
- 每帧减少 ~7000 次矩阵运算 + 数十次对象分配
- 鼠标视角转动不再附带拾取开销
- 低端机/高分屏自动降分辨率保帧率

## 验证
- `npx tsc --noEmit` 通过
- 游戏内 FPS 计数器对比优化前后
- 按住左键连续挖掘不再掉帧
- 红石灯/粉尘亮灭行为与优化前一致（回归验证）
